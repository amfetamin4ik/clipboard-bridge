# Мост — буфер обмена между устройствами

Статический сайт для GitHub Pages. Создайте мост, откройте его ссылку на втором устройстве и подключитесь. Вставьте текст и отправьте; на другой странице нажмите «Скопировать». Поддерживается двусторонний обмен текстом до 100 000 символов. Обе страницы должны оставаться открытыми. Доставка подтверждается вторым устройством.

## Если корпоративная сеть мешает соединению

Откройте режим HTTPS: `?mode=https`, либо нажмите «Не соединяется? Режим HTTPS» на главной странице. Создайте **новый** мост и откройте новую ссылку на втором устройстве. Ссылки обычного режима и HTTPS имеют разные способы подключения.

В этом режиме WebRTC и PeerJS не используются. Браузеры обмениваются зашифрованными сообщениями через публичный HTTPS API ntfy.sh на порту 443. Основной канал получения — Server-Sent Events. Если поток недоступен или буферизуется прокси, приложение использует короткие HTTPS GET-запросы каждые 15 секунд; при сетевой ошибке или лимите — через 60 секунд. В режиме опроса доставка текста может занимать до 30 секунд, подтверждение — дольше. Получение подтверждается после расшифровки на втором устройстве, а не после загрузки на сервер.

Каждый пакет шифруется AES-256-GCM с новым случайным 96-битным IV. Ключ выводится через HKDF-SHA-256 из случайного секрета ссылки и идентификатора комнаты. Секрет хранится в URL-фрагменте и не отправляется ntfy.sh. Сервер видит случайный идентификатор комнаты, IP-адреса, время, размеры запросов и шифротекст. Для подключения используется обмен свежими случайными идентификаторами вкладок и вызов/ответ; сообщения прежних сеансов не показываются после перезагрузки. Пакеты с неверным ключом или повреждённым шифротекстом игнорируются.

ntfy.sh временно кэширует зашифрованные сообщения (обычно до 12 часов). Длинный шифротекст передаётся одним зашифрованным вложением (обычно до 3 часов), что позволяет сохранить лимит 100 000 символов без множества мелких запросов. «Очистить» удаляет полученный текст только из текущей вкладки, а не кэш сервиса. Приложение не сохраняет ключи или текст в localStorage. Запросы Firebase отключены. Это дополнительная зависимость от внешнего публичного сервиса, без гарантии доступности.

Действуют ограничения ntfy.sh: на момент реализации 250 публикаций в сутки с IP, включая сообщения подключения и подтверждения, а также ограничения частоты запросов. Общий корпоративный IP может делить лимиты с другими пользователями. При HTTP 429 показывается ошибка; сообщение не считается доставленным. Если корпоративная сеть блокирует сам ntfy.sh или передачу данных наружу, этот режим тоже не соединится. Отключать защиту браузера, брандмауэр или проверку сертификатов не требуется.

## Обычный режим

Текст передаётся через WebRTC DataChannel. PeerJS Cloud используется для сигнализации. Включённая версия PeerJS содержит стандартные STUN и публичные TURN-серверы на порту 3478; отдельный TURN через TLS/443 не настроен. Некоторые корпоративные, мобильные сети и VPN могут блокировать такое соединение. Сообщения находятся в памяти вкладок; приложение не сохраняет их историю.

## Ссылки доступа

Ссылка содержит случайный идентификатор комнаты и секрет доступа в URL-фрагменте. Любой обладатель полной ссылки может подключиться к мосту и расшифровать его сообщения. Передавайте ссылку только доверенному устройству. Для новой сессии используйте «Новый мост». Не публикуйте ссылку в общедоступных каналах.

## Публикация и проверки

Settings → Pages → Deploy from a branch → main → / (root).

Запустите любой статический HTTP-сервер в этой папке. Clipboard API и криптография работают в HTTPS или localhost. Зависимость PeerJS 1.5.5 включена в vendor, лицензия MIT — рядом. Для тестов требуется Node.js 22+.

- `node test.cjs` — обычный режим: подключение, двусторонний текст, подтверждения, Unicode, неверный секрет, лимиты, очистка.
- `node test-https.cjs` — HTTPS с моделью сервера: шифрование, подключение, подтверждения, 100 000 символов, вложения, повторы, неверные ключи, ошибки сервиса, перезагрузка.
- `node smoke-https.cjs` — необязательная сетевая проверка двух клиентов через ntfy.sh. Передаёт только сгенерированный тестовый текст в случайной зашифрованной комнате и расходует лимит сервиса.

Документация: [публикация и ограничения ntfy](https://docs.ntfy.sh/publish/), [SSE и HTTPS-опрос](https://docs.ntfy.sh/subscribe/api/).
